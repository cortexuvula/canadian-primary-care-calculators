# Synthetic screenshot provenance

The three library/BSA images are generated by `e2e/public-screenshots.spec.js`; the three Batch A images by `e2e/batch-a-evidence.spec.js` from the compiled plugin in the test harness. There are no patient identifiers, patient records, system desktop captures or incidental application windows. The BSA example uses synthetic height 170 cm and weight 70 kg. Blank library views contain no measurements. Harness screenshots do not establish real Desktop mounting or OS clipboard behaviour.

Regenerate after `npm ci && npm run build`:

```sh
npx playwright install chromium
npx playwright test e2e/public-screenshots.spec.js e2e/batch-a-evidence.spec.js
```

Generated images first land in `.artifacts/public-screenshots/` and `.artifacts/batch-a-evidence/adapters/` (or `public-sdk/` in SDK mode). Inspect before copying the six named PNGs to `docs/screenshots/`. The Batch A receipt binds the actual runtime SHA256 and browser version, and the pixels themselves say SYNTHETIC / browser harness / NOT live Desktop. GA uses supplied EDD 2026-11-01 and explicit as-of 2026-10-01 (35+4); the LR example uses pretest20% and LRs5,2 with deliberate independence acknowledgement (71.4%); ACR uses albumin30mg/L and creatinine10mmol/L (3.0mg/mmol,27mg/g). These are synthetic examples, never patient records. Browser/OS/font versions may change screenshot pixels; runtime and release ZIP reproduction do not depend on reproducing pixel-identical screenshots. Committed image bytes are included verbatim in release checksums.
