# Contributing

Keep changes small and testable. Do not commit clinical values from real patients, credentials, local machine paths, generated test logs or private operational material. All examples, screenshots and fixtures must be synthetic.

Clinical changes require independent review of the equation, source populations, guards, unit conversions and reference vectors. Expected test values must be independently derived, not generated by the production function. Keep published source citations and limitations with the affected module. Do not add a questionnaire or third-party asset without resolving its redistribution terms.

Before proposing a change, run the commands in [verification](docs/verification.md). Preserve privacy/stale-result/copy/focus/reflow assertions; do not weaken tests to obtain a green run. Explain any change to clinical calculations or the reviewed runtime digest. Pure documentation/packaging changes should not modify the runtime.

`public-files.json` is the source and distributable allowlist. Add new source/test/docs files deliberately; no node_modules, downloaded SDK fixture, generated evidence, release archives or private development history belongs in the public package.

Report code defects through repository issues without patient information. Source review and passing tests are not clinical, legal or regulatory certification; do not claim native-host/clipboard behaviour was checked unless it actually was.
